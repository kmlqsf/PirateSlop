# Лут сундуков

Файл рядом: `ChestLoot.json`. Это единственный источник состава сетевых сундуков. Любой новый предмет для сундуков обязательно добавлять в `entries` этого файла. Старый список `DefaultLoot.asset.Items` продолжает управлять отдельными островными предметами и кандидатами необычного улова; сундуки его больше не используют. Локальный прототип сундука кита в эту систему пока не входит.

## Число разных типов в сундуке

```json
"chest": {
  "minItemTypes": 1,
  "maxItemTypes": 2
}
```

Сначала сервер выбирает точное количество разных типов от `minItemTypes` до `maxItemTypes`, включительно, затем гарантированно заполняет столько слотов. Допустимо `1 <= minItemTypes <= maxItemTypes <= 10`. При диапазоне 3–6 может быть выбрано 4: сундук получит ровно четыре разных типа. При 3–3 каждый новый сундук получает ровно три типа. В таблице должно быть не меньше `maxItemTypes` типов с положительным шансом.

Один слот сундука содержит один тип предмета и его стак. Типы в одном сундуке не повторяются; максимум — десять занятых слотов. Количество предметов в стаке задаётся независимо от числа типов.

## Список предметов

| Поле | Значение |
| --- | --- |
| `item` | Точное английское имя из `InventoryItem`, например `Fish` или `Cannonball`. Регистр важен. |
| `name` | Название для чтения файла человеком. Игровые названия и иконки остаются в `InventoryIcons`. |
| `chancePercent` | Частота выбора типа относительно других оставшихся типов, от 0 до 100. 0 отключает выпадение. Сумма процентов не ограничена. |
| `minCount` | Минимальное число предметов в выпавшем стаке, включительно. |
| `maxCount` | Максимальное число предметов в выпавшем стаке, включительно. Допустимый диапазон: от `minCount` до 1000. |

Для каждого слота выбор делается из ещё не выбранных типов пропорционально их `chancePercent`. Тип с 25 выбирается в 2,5 раза чаще типа с 10, пока оба доступны. После выбора тип исключается из кандидатов этого сундука. Десять предметов с 25 каждый допустимы: сумма 250 не является ошибкой, для первого слота каждый имеет одинаковый шанс 10%. Эти значения управляют частотой выбора при обязательном заполнении; они не являются независимой вероятностью присутствия в целом сундуке. Значение 100 само по себе не гарантирует присутствие, если конкурируют другие включённые типы.

Размер выбранного стака отдельно разыгрывается между `minCount` и `maxCount`, включительно. Например, при 2–5 выпадает от двух до пяти единиц. Чтобы сундук гарантированно содержал десять конкретных типов, установить 10–10, оставить положительные шансы только у этих десяти типов, остальные отключить.

Количество типов задаётся только секцией `chest`; прежнее поле `DefaultLoot.asset.ItemsPerChest` удалено. Начальные проценты пересчитаны из прежних весов; все размеры стаков установлены в 1–1. Поддерживаемые предметы, которых раньше не было в сундуках, перечислены с шансом 0. Доски исключены: текущий инвентарь запрещает их добавление.

Чтобы включить предмет с шансом 0, назначить ему положительный процент. Чтобы отключить — поставить 0. Менять проценты других предметов не нужно. Идентификатор `item` менять только при выборе другого игрового типа; `name` можно свободно редактировать.

## Изменение во время работы

Сохранить JSON на машине сервера/хоста. При следующем наполнении сундука сервер перечитает файл. Перезапуск и перекомпиляция не нужны. Содержимое уже созданных сундуков не меняется. Клиенты получают типы и количества предметов через FishNet; их локальная таблица не определяет награду.

Расположение морских событий использует отдельный генератор случайных чисел: изменение списка предметов, шансов и размеров стаков не меняет координаты событий при том же seed карты.

В Windows-сборке файл находится в `<ИмяИгры>_Data/StreamingAssets/Loot/ChestLoot.json`. Файл из проекта включается в сборку автоматически.

При неверном JSON, неизвестном/повторяющемся предмете, неверных количествах, недостаточном числе включённых типов или отдельном шансе вне диапазона 0–100 сервер оставляет последнюю корректно прочитанную таблицу и пишет предупреждение. Если корректная таблица ещё не была загружена, наполнение завершается ошибкой; скрытого перехода на старый каталог нет. JSON не поддерживает комментарии и запятые после последнего элемента.

Клик по стаку забирает столько предметов, сколько помещается в инвентарь; остаток остаётся в сундуке. Рыба, ром и ядра подчиняются существующим лимитам инвентаря. Несколько единиц оружия занимают несколько обычных слотов.

## Подключение нового лута

1. Реализовать предмет в `InventoryItem`, серверном инвентаре и системе использования.
2. Подключить сетевой префаб, сброс предмета и иконку к существующим системам.
3. Обязательно добавить строку в `ChestLoot.json`, указать положительную частоту выбора и диапазон стака.

Неизвестные названия не превращаются в новые игровые предметы автоматически. Для нового типа нужен код предмета и совместимая версия игры у участников. Изменения только процентов и количества существующих типов не требуют изменения протокола.
