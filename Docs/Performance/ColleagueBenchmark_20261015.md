## Что именно происходит

Уже в первые65с —20.63 FPS, GPU20.70мс. На участке флота главный поток48.81мс против GPU22.18мс: ведущий предел здесь на CPU. Из wall-clock фаз: Update14.46мс, PreLateUpdate14.89мс, PostLateUpdate11.89мс; отдельно есть FixedUpdate. Это реальная стоимость скриптов/физики/подготовки рендера, а не признак ограниченияFPS.

Один корабль находится внутри водоворота уже в первом сэмпле; остальные входят в26.59–27.61с. К150с минимальное расстояние между центрами кораблей по XZ19.92м. Около192с они находятся наY−89…−102м, расстояние одной пары17.34м. Это подтверждает тяжёлую ситуацию сближения/контактов воронки; наличие конкретного контакта каждой пары JSON само по себе не доказывает.

В190–200 с —4.50 FPS, GPU40.98мс, ShipPhysicsSync67.18мс и PlayerSyncTransforms23.25мс в среднем на кадр. В200–210 с —5.42 FPS, соответствующие синхронизации53.23/22.48мс. Это вложенные времена, их нельзя складывать с ShipTick или Update. На отдельных кадрах ShipPhysicsSync достигает101.54мс. Остаётся подтверждённая дорогая синхронизация физики при таком состоянии флота.

При190–200 с выполняется в среднем11.13шагов FixedUpdate на видеокадр против2.43в первые65с. Это соответствует примерно50шагам/с при4.5 FPS и указывает на множество догоняющих шагов в одном кадре. Снижение частоты серверной симуляции не применялось и не предлагается как маскировка проблемы.

GPU также дорог:29.63мс в среднем в шторме и около41–48мс в худших десятисекундных окнах. Для RTX 3050 QHD с такими эффектами тяжёлое условие. Уменьшение разрешения может помочь GPU, но не устранит подтверждённые CPU-синхронизации в десятки миллисекунд.

За запись выделено1.357 GB managed-данных, примерно5.66 MB/с;54 события сборки GC по счётчику поколения0. Одинаковые изменения счётчиков поколений1/2 не считать ещё108отдельными паузами. Пик428.86мс около168.47с не подтверждён как GC-пауза: соседние записи не показывают сборки. Следующая запись содержит362.59мс в TimeUpdate; для причины нужны нативный профиль/внешние данные. Используемая память2.417→2.748 GB; одного четырёхминутного прогона недостаточно, чтобы объявлять утечку. Ошибок0;13предупреждений относятся к неподдерживаемому Camera.layerCullSpherical в URP, в основном во время подготовки, и не объясняют весь профиль.

## Следующий контроль на этом ПК

1. Передать одну и ту же актуальную сборку на оба ПК; записать buildGUID.
2. Перезапустить игру, выключить стресс сближения в водовороте и HUD; сохранить одинаковые графические настройки.
3. Для масштабирования запустить новый «Тест флота:4корабля»; для полного окружения — обычный «Тест производительности». Сценарии между собой не смешивать.
4. Первый контроль — QHD / render scale 1, затем тот же сценарий в1920×1080. Сильное снижение GPU-времени без сопоставимого ростаFPS подтвердит оставшееся ограничение CPU.
5. Для количественного сравнения — по 3 одинаковых запуска, предпочтительно Release без Profiler. Development также полезен, но сравнивается отдельно. Стресс водоворота сохраняется отдельным нерешённым случаем.

Пока нельзя честно назвать точную долю влияния железа, Development, повторного запуска или HUD: здесь нет парных контролей. Этого отчёта достаточно для выбора следующих проверок, но недостаточно для точной оценки разницы быстродействия двух ПК.
