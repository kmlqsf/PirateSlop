# Анимации персонажа через MCP

Работать через подключённые Blender MCP и Unity MCP. Не запускать отдельные процессы редакторов. Билды и Play Mode запускает пользователь.

## Повторяемый маршрут

1. Открыть `Art/Blender/Characters/PirateSabreAttack.blend`, сцена `SabreAnimationStudio`. Сначала сохранить отдельно текущую несохранённую работу. Здесь заново импортирован игровой `Assets/Models/Characters/Pirate/PirateCharacter.fbx`, без старой анимации удара.
2. Использовать `pose_studio.py`: `reach` ставит руку по цели и локтевому ориентиру, `grip` задаёт полный базис кисти и сгиб пальцев, `socket` создаёт крепление, `bake` записывает позы, `export` экспортирует только скелет, связанные меши и указанные сокеты.
3. Описать нужное действие коротким Python-рецептом по примеру `sabre_attack.py`: ключевые времена, цели кистей, ориентация предмета, корпус. Создавать новое действие с отдельным именем. Для мушкета обе кисти должны удерживать свои точки на одном предмете; для трубы основная цель — окуляр около глаза.
4. Исполнить рецепт внутри живого Blender MCP через `exec(compile(...), {'__file__': path, '__name__': '__main__'})`. Помощник импортируется из папки рецепта. Повторный запуск сабли обновляет те же действия и FBX.
5. В Unity вызвать `CharacterActionImport.Import(name, loop)`: Generic-импорт, ретаргет на игровой скелет и обновление существующего `.anim` с сохранением GUID. Затем назначить клип нужному состоянию и подключить запуск к действию предмета.

Сабля: после рецепта вызвать `CharacterActionImport.ImportSabre()` или меню `PirateSlop/Import Sabre Actions`. Это обновляет оба клипа, существующий слой `SabreCombat`, переход обратно в стойку и хват в `NetworkPlayer.prefab`. Предмет остаётся отдельным; `WeaponSocket_R` в исходном FBX передаёт ориентацию крепления в Unity. Скрипт `SabreAnimation` использует один хват для тела и рук первого лица.

`SabreSlash`: 0.9 секунды, замах до 0.30, активный удар 0.30–0.48, завершение и возврат до 0.90. Серверное окно урона в `PirateWeaponAnimation.cs` уже совпадает; новый клип не назначает урон через AnimationEvent. Существующая сетевая рассылка запускает удар у наблюдателей.

Для следующего предмета переиспользовать помощники и импорт, добавить только рецепт, точки хвата и связь с его игровым действием. Не перестраивать весь контроллер, не менять скелет и не запускать общий Configure Player Animations ради одного клипа. После импорта проверить компиляцию и ссылки; визуальная и сетевая приёмка остаются ручными.
